## 5. Business rules

| Rule                                         | Status                                                                                    | Evidence                                                                                                                                                                                                            |
| -------------------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. End date after start date                 | ⚠️ implemented **literally** (strictly after → no single-day leave), documented in README | `apps/api/src/modules/vacation-requests/domain/date-range.ts`, CHECK `vr_end_after_start` → `apps/api/src/modules/vacation-requests/domain/date-range.test.ts`, `apps/api/test/integration/vacation-create.test.ts` |
| 2. No overlapping requests for the same user | ✅ (pending + approved block; inclusive; concurrency-safe)                                | handler pre-check + `EXCLUDE USING gist` + per-user lock → `apps/api/test/integration/vacation-create.test.ts` (10-way race), `apps/api/test/integration/schema-constraints.test.ts`                                |
| 3. Approved requests cannot be modified      | ✅ (approved and rejected are terminal)                                                   | aggregate + compare-and-set + CHECK → `apps/api/test/integration/vacation-decide.test.ts`                                                                                                                           |
| 4. No requests in the past                   | ✅ (today allowed; business time zone)                                                    | aggregate + injected clock → `apps/api/test/integration/vacation-create.test.ts`                                                                                                                                    |
| 5. Rejected request must have a comment      | ✅                                                                                        | aggregate + CHECK `vr_rejection_needs_comment` → `apps/api/test/integration/vacation-decide.test.ts`                                                                                                                |
| 6. Only validators approve or reject         | ✅                                                                                        | route roles + handler checks → `apps/api/test/integration/rbac.test.ts`                                                                                                                                             |
